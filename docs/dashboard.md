# KODA 산학과제 대시보드 요구사항

디지털 자산에 익숙하지 않은 법인 이용자가 자산 현황과 처리 상태를 이해하고, 필요한 확인과 승인을 거쳐 업무를 수행할 수 있도록 대시보드의 정보 구조와 이용 흐름을 개선한다.

## 탭별 설계 기록 형식

실제 탭을 확인한 뒤 탭마다 아래 항목을 한 묶음으로 작성한다. 아직 확인하지 않은 탭 이름·페이지 크기·권한을 확정값으로 넣지 않는다.

| 항목 | 기록할 내용 |
| --- | --- |
| 탭·이용자 과업 | 탭 이름, 이용자 역할, 가장 자주 수행하는 업무 |
| 정보 위계 | 먼저 알아야 할 정보, 보조 정보, 상세 화면에서 제공할 정보 |
| 목록 탐색 | 데이터량 가정, 검색·필터·정렬, 페이지 크기, 탐색 방식과 선택 이유 |
| 상태와 행동 | 상태별 표시, 다음 행동, 권한에 따른 노출·실행 차이 |
| 예외 상황 | 빈 목록, 검색 결과 없음, 로딩·오류, 긴 텍스트·많은 항목 |

## 후속 정의가 필요한 항목

- 실제 탭 목록, 주요 이용자 역할, 요청·승인 상태와 권한 체계
- 공유 가능한 서비스 화면과 테스트 환경의 범위
- 익명화된 법인 고객 인터뷰와 사용자 과업 우선순위
- 주소·네트워크 등 서비스가 지원하는 검증 규칙과 오류 안내 범위
- Market Insight의 기관 선정·콘텐츠 선별 기준, 이용 권한과 표시 가능 범위
- 고객사별 맞춤 리서치의 필요성, 허용 데이터, 제공 방식과 과제 범위 포함 여부
- 기능별 개발 범위, 담당과 일정

각 항목의 결정은 [의사결정 기록](decisions.md)에 근거와 함께 남긴다.
