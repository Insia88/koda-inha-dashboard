# 공개 데모 시연 가이드 (3분)

대상: KODA × 인하대 산학과제 중간발표·검토 시연. 공개 데모(https://koda-inha-dashboard.vercel.app)는 **모의 데이터·개발용 로그인·모의 커스터디**로만 동작한다(DEC-004). 실제 계정·자산과 연결되지 않는다.

## 시연 5분 전 체크리스트

1. `cd app && node scripts/prewarm-demo.mjs https://koda-inha-dashboard.vercel.app` — healthz·로그인·역할별 API를 미리 호출해 콜드 스타트와 첫 요청 지연을 줄인다. 출력의 `instance=` 값이 여러 곳이어도 공유 상태(Blob) 덕분에 데이터는 같다. BLOB 연결이 꺼져 있으면(환경변수 제거) 예전처럼 인스턴스별로 갈라진다.
2. 브라우저에서 **깨끗한 주소** `https://koda-inha-dashboard.vercel.app/login` 을 연다(`?reason=expired`는 세션 만료 안내가 떠 첫 장면이 지저분해진다). 영상이 자동재생되는지 확인하고, 오른쪽 아래 **'배경음 켜기'** 로 배경음을 켠다(브라우저가 소리 자동재생을 막는 경우가 있다). `prefers-reduced-motion`이 켜진 기기에서는 영상·소리 버튼을 숨기는 것이 정상이다.
3. 로그인 화면에서 추천 순서대로 **한지수(자산 담당자) → 오민재(승인자) → 문태호(감사 담당자)** 로 들어가 본다. 공개 데모의 상단 **「데모 사용자 전환」** 으로 로그아웃 없이 역할을 바꿀 수 있다.
4. 세션은 480분 뒤 만료되고(데모용으로 늘렸다), 재배포 때 데이터가 초기화되는 것을 확인한다(DEC-004·DEC-008). 시연 직전에는 배포하지 않는다.
5. 데이터는 Vercel Blob 공유 스냅샷으로 인스턴스 간 통일되어 있고, '다른 데모 서버' 안내는 표시되지 않는다(DEC-008). 그래도 **시연 중 새로 고침·재배포는 피한다**(재배포하면 데이터가 초기화되고, Blob 확인 지연으로 몇 초 늦게 반영될 수 있다). 감사 비트는 승인 **이전**에 보여 주고, 승인은 마지막에 성공 안내만 보여 준 뒤 화면 이동을 하지 않는다.

## 알려진 한계 (시연 중 질문 대비)

- 감사 기록은 왼쪽 **「업무 기록만 보기」** 가 기본으로 켜져 있어 로그인·로그아웃 기록이 첫 화면을 덮지 않는다. 전체 기록은 체크를 끄거나 행동 필터를 비우면 본다.

- 데이터는 **Vercel Blob 공유 스냅샷**으로 인스턴스 간 통일되어 있다(DEC-008). 변경은 수 초 안에 모든 인스턴스에 전파되고, 재배포하면 초기 상태로 돌아간다. 로그인은 서명 쿠키라 유지된다.
- 공유 저장소 확인에 수백 ms가 붙을 수 있고, 동시에 두 사람이 쓰면 마지막 쓰기가 이긴다(데모는 한 사람이 순서대로 조작). 데모 직전에는 새 배포로 데이터를 초기화하고 다른 테스트를 멈춘다.
- 로그인 한도는 IP당 1분 30회, 전체 요청 한도는 분당 600회다(모의 데모 보호).
- 영상은 42.45초 무음 루프이며, 자동재생이 차단되면 포스터가 보인다(장식이므로 데모 진행에는 지장 없음).
- 배포 보호는 꺼져 있다(DEC-004). KODA 로고·Suno 음악은 별도 권리 확인 대상이다.

## 공개 사이트 (첫인상용)

발표 시작 전에 브랜드 사이트 **https://koda-inha-dashboard.vercel.app/site** 를 먼저 열어도 좋다(비로그인으로 루트 `/`에 오면 이 사이트로 이동한다). 구성은 참조 사이트와 같은 순서다: 히어로 → 바뀌는 것 3가지 → 브랜드 필름·장면 6개 → 화면 6장 → 자료 3종 → 도입 안내. 상단 내비 마지막 **「대시보드」** 를 누르면 이 대시보드 로그인으로 온다. 사이트의 소개서·3분 데모 가이드 PDF도 발표 전 확인용이다. 사이트와 대시보드 모두 모의 환경이며 실제 자산·고객 정보가 없다.
