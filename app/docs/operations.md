# 운영 도입 전 남은 조건

이 앱은 개발 환경에서 기능·권한·데이터 일관성을 검증하기 위한 것이다. 아래가 충족되기 전에는 실제 고객·자산에 사용할 수 없다. UI·테스트 통과가 인증·보안·규제 적합성을 증명하지 않는다.

## 반드시 교체·구현할 부분
| 영역 | 현재 | 운영 조건 |
| --- | --- | --- |
| 인증 | `AUTH_MODE=dev` 비밀번호 없는 모의 로그인. `NODE_ENV=production`이면 서버가 기동을 거부 | KODA SSO/OIDC 어댑터 구현(`server/auth.ts`의 세션 생성부 교체), MFA·세션 만료 정책·재인증(승인 직전) 결정, `/api/auth/dev-users` 제거 |
| 커스터디 | `MockCustodyAdapter` — 일정 시간 뒤 '처리 완료'로 표시만 함 | 실제 커스터디 API 어댑터(`server/adapters/custody.ts` 인터페이스), 서명·콜드룸 절차와 상태 매핑, 실패·부분 처리·재시도 규칙, 외부 호출 멱등 키 |
| 주소 검증 | `MOCK-` 형식만 허용 | 네트워크별 실제 주소 형식·체크섬 검증 어댑터, 지원 자산·네트워크 목록을 KODA 기준으로 동기화 |
| 시세 | 고정 모의 값 | 시세 제공처 계약·출처 표기·지연 기준 결정 |
| 저장소 | 단일 파일 SQLite | 다중 인스턴스면 PostgreSQL 등으로 이전(동일 제약: 부분 고유 인덱스, 감사 불변 트리거·권한 분리, `SELECT … FOR UPDATE` 또는 버전 검사), 백업·암호화·보존 기간 |
| 감사 기록 | 조직별 해시 체인 + UPDATE/DELETE 금지 트리거 | DB 계정 권한 분리(앱 계정 INSERT만), 외부 WORM 저장소 또는 주기적 해시 앵커링, 보존·열람 정책 |
| 요청 한도 | 프로세스 메모리 기반 | 여러 인스턴스면 공유 저장소(Redis 등) |
| 비밀값 | 없음(개발 모드는 비밀값 불필요) | 쿠키 `secure` 활성(HTTPS), 비밀값 관리 시스템 |

## KODA 측 확인이 필요한 자료
- 실제 역할·권한 매핑, 요청 상태 체계와 전이, 승인 인원·한도 정책 (`assumptions.md` A-01~A-05)
- 주소록 등록 절차·확인 주체, 지원 네트워크별 메모/태그 규칙
- Market Insight 기관 화이트리스트 운영 기준, 원문 표시·이용 권한
- 익명화된 법인 고객 인터뷰(사용자 과업 우선순위) — 현재 미수령

## 보안 점검 항목(구현됨, 운영에서 재검증 필요)
서버 측 역할·조직 검사(모든 API), 타 조직 리소스 404, CSRF 헤더 + SameSite=Strict, HttpOnly 세션·서버 폐기, 입력 Zod 검증·본문 64KB 제한, 오류 응답에 스택·내부 값 없음, 로그에서 쿠키·CSRF 가림, CSP·보안 헤더, CSV 수식 무력화, 내보내기 권한·기록.
