# 문제 → 개선 → 요구사항 → 검증 결과 (DASH-006)

"검증"은 이 저장소의 자동 테스트·실제 브라우저 확인 결과다. **실제 사용자 테스트·인터뷰는 수행하지 않았으며**, 개선율·소요 시간 등 효과 수치는 측정하지 않았다. 아래 "기대 효과"는 모두 검증 전 가설이다.

상태 표기: **해결**(프로토타입에서 문제 상황을 막거나 바꿨고 테스트가 있음) · **일부**(일부만 바뀌었거나 화면이 남음) · **미해결**(바꾸지 않음, 이유 기록) · **가설**(효과를 측정하지 않은 설계 판단). 검증 칸에는 테스트 이름을 적고, 자동 검사가 없으면 '검증 안 됨'으로 적는다. 설계 가정 ID(A-xx)는 `assumptions.md`, 제안 ID(DEC-xxx)는 `../../docs/decisions.md`.

**A2b 덧붙임 — 위 `flow.spec.ts` 간헐 실패의 원인 (2026-10-21):** 비동기 조회가 끝나면서 등록 양식이 초기화된 것이 아니라, 떠나는 주소록 화면의 필터가 다음 화면 주소에 쓰인 화면 버그였다. `src/main.tsx`의 `<RouterProvider>`는 화면 전환을 React transition으로 그린다(react-router 8.4.0 기본값). 그래서 「주소 등록」을 누른 직후 주소창(`window.location`)은 이미 `/addresses/new`인데, 주소록 목록은 전환이 끝날 때까지 화면에 남아 입력을 받는다. 그 목록에는 접근 가능한 이름이 같은 '자산' 필터(`<span class="sr-only">자산</span>`)가 있어 `getByRole('combobox', { name: /^자산/ })`가 이 틈에 그 필터를 잡을 수 있다. 필터의 `useUrlState.set`은 `setSearchParams(…, { replace: true })`를 부르고, 이 값은 이미 바뀐 위치를 기준으로 풀려 주소가 `/addresses/new?assetCode=USDC`가 된다. 그 뒤 새로 그려진 등록 양식은 자기 상태(`EMPTY`)로 시작하므로 자산 선택이 '자산 선택'(처음 값)으로 보였다. 등록 양식 안에는 자산 값을 지우는 코드가 없다(네트워크 효과는 `networkCode`만 바꾸고, 목록은 캐시를 쓰고, `AuthGate`는 로그인 정보가 없을 때만 대체 화면을 보이며, `Layout`의 `<Outlet/>`에는 key가 없다).
재현: 클릭과 목록 필터 변경을 한 작업 안에서 일으킨 임시 검사 두 번(같은 작업·다음 매크로태스크) 모두 변경 시점에 `{path:'/addresses/new', listFilterStillMounted:true, formMounted:false}`, 끝 상태 `{path:'/addresses/new?assetCode=USDC', formAsset:''}`. 보통 흐름 30회(CPU 1배 15회·4배 15회)에서는 경합이 나지 않았고, 4배에서 스냅샷 12개 중 3개가 주소창은 `/addresses/new`인데 목록 DOM이 남아 있는 상태였다. A2 전체 실행에서 한 번만 실패한 것과 맞는다.
고침: `src/hooks.ts` `useUrlState.set`이 이 화면을 그린 경로(`useLocation().pathname`)와 주소창 경로가 다르면(이동 중) 쓰지 않고 버린다. `useUrlState`를 쓰는 모든 목록(주소록·활동 내역·감사 기록·결재 및 요청·Market Insight·인사이트 관리)과 `SearchField`의 지연 검색에 함께 적용된다. 버린 값은 떠나는 목록의 필터일 뿐이라 보안 영향은 없다. 전역으로 transition을 끄는 방법(`useTransitions={false}`)은 포커스 처리·작성 중 보호 시점까지 바꾸고 한 작업 길이의 틈은 그대로 남아 쓰지 않았다.
검사: `interaction.spec.ts` '화면 이동 중 떠나는 목록의 필터 변경은 다음 화면 주소에 붙지 않는다'(한 `page.evaluate` 안에서 링크 클릭과 필터 `change`) — 고치기 전 HEAD 4e7268a에서는 주소가 `?assetCode=USDC`로 끝나 실패, 고친 뒤 통과. `flow.spec.ts`는 「주소 등록」·「출금 요청 작성」을 누른 뒤 그 화면의 h1이 보일 때까지 기다리고 자산을 고른다(다른 `/^자산/` 검사는 모두 `page.goto`로 시작해 바꾸지 않음).
