# 설계 가정 (변경 가능)

실제 KODA 상태 체계·권한·정책 자료가 없는 부분은 아래 가정으로 구현했다. 근거 자료가 확보되면 해당 항목과 코드 위치를 바꾼다. 요구사항 출처는 `../../docs/dashboard.md`, 결정 대기 항목은 `../../docs/decisions.md`의 OPEN-xxx.

| ID | 가정 | 코드 위치 | 관련 |
| --- | --- | --- | --- |
| A-01 | 역할은 자산 담당자(requester)·승인자(approver)·감사 담당자(auditor)·조직 관리자(admin)·KODA 운영자(operator) 5종. 한 사람이 여러 역할 가능 | `server/authz.ts` | DASH-004, OPEN-002 |
| A-02 | 출금 요청 상태: 작성 중 → 검토 중 → 승인 대기 → 처리 중 → 처리 완료/처리 실패, 반려, 취소. '검토'는 요청자가 받는 주소·수량을 최종 대조하는 단계 | `server/domain/requests.ts` `TRANSITIONS` | DASH-004 |
| A-03 | 승인 정책: 기본 1명, 원화 평가액 1억 원 이상은 서로 다른 2명. 요청자는 자기 요청 승인 불가(API + DB 트리거) | `config/policy.json` | DASH-004 |
| A-04 | 승인 대기 진입 시 수량을 예약하고 반려·취소·실패 시 해제, 완료 시 차감 | `requests.ts` | DASH-001 |
| A-05 | 주소 등록은 등록자가 아닌 승인자가 원본과 대조해 확인해야 '사용 가능'. 등록·확인·제출 시 주소 끝 6자리 재입력 | `config/policy.json`, `addresses.ts` | DASH-003 |
| A-06 | 주소 형식 점검은 개발용 `MOCK-` 형식만 허용. Ethereum·Kaia는 같은 형식(EVM)으로 두어 형식만으로 네트워크를 구분할 수 없는 실제 위험을 재현 | `shared/address-rules.ts` | DASH-003 |
| A-07 | 유사 주소: 고유부 앞 6자·뒤 4자가 같고 전체가 다른 주소를 경고(차단하지 않음) | `isLookalike` | DASH-003 |
| A-08 | XRP Ledger는 데스티네이션 태그(0~4294967295) 필수 | `catalog.ts` | DASH-003 |
| A-09 | 스테이킹은 조회 전용. 신청·해제 절차와 권한 자료가 없음 | `pages/Staking.tsx` | — |
| A-10 | 지갑 생성·구성원 초대는 운영 SSO·KODA 절차 확인 전이라 제공하지 않음 | — | — |
| A-11 | Market Insight는 KODA 운영자가 화이트리스트 기관 자료만 게시·숨김. 고객 조직은 게시+화이트리스트 자료만 조회 | `app.ts`, `config/insight-policy.json` | DASH-007, OPEN-004 |
| A-12 | 네트워크 수수료는 표시하지 않음(산정 규칙 자료 없음) | — | — |
| A-13 | 시세는 모의 값이며 30분 넘게 갱신되지 않으면 '시세 지연' | `config/policy.json` | DASH-001 |

메뉴 구성(잔고·자산 활동 내역·결재 및 요청·스테이킹·지갑 관리·주소록 관리·토큰 목록·조직 관리·감사·마켓 인사이트)은 기존 화면 캡처의 메뉴에서 가져왔다. 메뉴가 존재한다는 사실만으로 각 메뉴의 실제 기능·권한·운영 정책이 확인된 것은 아니다.
