## 서체
- 본문: Pretendard Variable → 맑은 고딕 → Apple SD Gothic Neo → 시스템 글꼴. Pretendard는 `pretendard` 1.3.9 패키지의 가변 글꼴 동적 서브셋(OFL-1.1)을 `src/main.tsx`에서 불러온다. 빌드 때 글꼴 파일이 `dist/assets`에 들어가 앱과 같은 출처에서만 내려받고(외부 CDN 없음), 화면에 쓰인 글자 범위의 파일만 받는다. 같은 출처 로딩은 번들 구성으로 보장한다. 현재 CSP의 `font-src`는 `'self' https: data:`이므로 CSP가 글꼴 출처를 `'self'`로 막아 주지는 않는다(e2e/display.spec.ts가 글꼴 요청 출처를 확인한다). 라이선스 원문은 `public/fonts/PRETENDARD-LICENSE.txt`로 함께 배포한다. 글꼴을 받지 못하면 시스템 글꼴로 보인다.
- 15px / 행간 1.55. `word-break: keep-all`, 줄바꿈은 `overflow-wrap: break-word`. 한 글자 단위 줄바꿈(`anywhere`)은 주소(`.addr-code`)·고정폭(`.mono`)·긴 셀(`.cell-wrap`)과, 사용자가 입력한 이름·받는 곳·목적이 들어가는 칸(화면 제목·설명 `.page-header`, 정의 목록 값 `.dl dd`, 요청 목록 보조 줄 `.req-meta`)에만 쓴다. 전역에 쓰면 표 열이 한 글자 폭으로 무너진다.
- `break-word`는 칸의 최소 폭을 줄이지 않는다. 띄어쓰기 없는 한글(keep-all에서는 한 단어)이 들어갈 수 있는 flex·grid 칸은 `min-width: 0`이나 `minmax(0, 1fr)`로 줄어들 수 있게 한다(`1fr`은 `minmax(auto, 1fr)`이라 긴 단어 폭만큼 밀린다). 390px에서 최대 길이(이름 60자·받는 곳 80자·목적 200자) 값으로 확인한다(e2e/responsive.spec.ts).
- 제목: 같은 서체 700. h1 24px, h2 17px.
- 숫자: `font-variant-numeric: tabular-nums`, 표의 숫자 열은 머리글과 본문 셀 모두 오른쪽 정렬(좁은 화면의 쌓인 카드에서는 왼쪽). 주소·참조번호: Cascadia Mono → D2Coding → Consolas. 참조번호(`.ref`)와 날짜 입력 레이블은 줄을 바꾸지 않는다.

## 간격·모양
4px 배수(4·8·12·16·24·32·48). 카드 반경 8px, 입력 6px. 최소 클릭 영역 40px(작은 버튼 32px).

## 숫자·단위·시각
- 수량은 자산 최소 단위까지 정확한 문자열로 표시하고 단위(`BTC`)를 붙인다. 표시 포맷(`1,234.5`)과 저장값(최소 단위 정수 문자열)은 분리한다.
- 원화 평가액은 "약 55.11억 원" 보조 표기 + 정확한 원 단위를 함께 둔다. 평가액 옆에는 **시세 기준 시각(KST)·출처·데이터 상태 배지**(모의 데이터 / 시세 지연 / 시세 없음)를 항상 둔다(`DataStamp`). 항목 사이 구분점(·)은 글자로 넣지 않고 CSS가 그리며, 줄이 바뀐 첫 항목 앞에는 보이지 않는다.
- 예약 수량이 0이어도 단위를 붙인다(`0 BTC`, 흐린 글자).
- 날짜·시각은 `YYYY-MM-DD HH:mm` (KST).

## 상태 표현
- 요청: 작성 중(neutral) → 검토 중(info) → 승인 대기(warning) → 처리 중(info) → 처리 완료(success) / 반려·처리 실패(danger) / 취소(neutral). 문구와 설명은 `shared/terms.ts` 단일 출처.
- 4단계 진행 레일(작성·검토·승인 대기·처리 결과)을 목록·홈·상세에서 같은 모양으로 쓴다. 현재 단계는 `aria-current="step"`.
- 상태 배지 옆에는 누구 차례인지 짧은 글자를 흐린 색으로 붙인다(`REQUEST_STATUS[*].turn`, 표시용): 작성 중 '요청자 작성 중', 검토 중 '요청자 최종 확인 중', 승인 대기 '승인자 결정 대기', 처리 중 '수탁사 처리 중'. 상태 이름·색은 바꾸지 않는다. 홈 진행 중 요청에서 지금 내가 승인할 차례인 요청에는 Ink 테두리의 '내 승인 차례'를 붙인다. 홈 진행 중 요청은 첫 줄에 번호·상태·'내 승인 차례'·수량만 두고(수량이 줄마다 같은 자리), 누구 차례인지는 둘째 줄 맨 앞('승인자 결정 대기 · 요청자 → 받는 곳 …')에 쓴다.
- (A2-1) 승인 대기 요청은 둘째 줄 맨 앞(`.turn-text` 자리)에 지금 승인할 수 있는 사람과 '승인 요청 n시간째'(요청 상세와 같은 이름)를 쓴다: 내가 후보가 아니면 '다른 사람 차례: 서예린·오민재 · 승인 요청 4시간째', 내가 후보면 '승인할 수 있는 사람: 나·서예린 · 승인 요청 4시간째'(첫 줄 '내 승인 차례' 배지는 그대로), 후보가 없으면 '승인할 수 있는 사람 없음 · 승인 요청 4시간째'. 후보가 1명 이상이지만 남은 승인보다 적으면 끝에 경고 색 굵은 글자 ' · 승인할 사람 부족'을 붙인다(글자가 뜻을 전하고 색은 보조, 요청 상세의 경고 Notice와 같은 판정, 후보 0명은 머리 문구가 이미 '없음'이라 붙이지 않음). 이름은 서버 순서(이름순)로 최대 3명, 나머지는 '외 n명', 본인은 '나'로 맨 앞. 이름 줄을 보인 행은 같은 줄에 상대 시간이 두 번 오지 않게 끝의 시각을 절대 시각만 두고 '(n시간 전)'을 뺀다. '승인 요청'과 시간은 한 덩어리로 줄을 바꾸지 않는다. 서버가 후보를 주지 않는 요청(승인할 수 없는 요청)은 A1 차례 문구와 '(n시간 전)' 그대로다. 이름이 길면 390px에서 줄을 바꿀 수 있다. '지금 처리할 일'의 승인할 출금 요청 한 줄 목록도 같은 '승인 요청 n시간째'를 쓴다(같은 요청이 두 카드에서 다른 숫자로 보이지 않게).
- 기다린 시간은 'n분째'·'n시간째'·'n일째'(내림, 1분 안은 '1분째')로 쓰고 `<time dateTime>`과 KST 절대 시각 `title`을 붙인다(`WaitedTime`). **지연 색·기준 시간은 쓰지 않는다**(만료·지연 판단은 KODA 결정).
- 레일 마지막 칸 '처리 결과'는 승인 대기·처리 중 요청 상세에서 레일 바로 아래 한 줄로 설명한다(필요한 승인이 모두 모인 뒤 수탁사가 처리한 결과). 네 단계 이름은 그대로다.
- 상세 화면 상단의 **다음 할 일** 패널(Ink 바탕 + Green 테두리)은 역할별 문장 하나만 보여 준다. 이 대시보드는 알림을 보내지 않으므로 '알려 드립니다' 같은 약속을 쓰지 않고, 어디에 나타나는지와 직접 알려야 한다는 점을 쓴다. 패널 안 링크는 밝은 녹색(#B9F3DD) 글자다. 패널 안 요소의 포커스 링은 같은 굵기(3px)의 `--focus-on-dark`다(A3). 패널 자체(`tabindex="-1"`)의 링은 바깥 2px, 밝은 바탕 위에 그려지므로 파랑 그대로다.
- (A2-1) 승인 대기이고 승인할 수 있는 요청이면 패널의 역할별 문장 아래에 한 단계 작은 글자(14px, 이름만 굵게)로 '승인할 수 있는 사람: 강도윤 · 서예린 · 오민재 (남은 승인 2명) · 승인 요청 4시간째'를 둔다(본인은 '나'로 맨 앞, 0명이면 '없음', '승인 요청 4시간째'는 홈과 같은 한 덩어리). 요청자에게는 그 아래 흐린 줄 '본인이 작성한 요청은 승인할 수 없습니다. 승인 x/y명. 승인자 역할은 「조직 관리」의 역할 표에서 볼 수 있습니다.'(링크 유지). 남은 승인을 채울 사람이 모자라면 패널 바로 뒤에 경고 Notice('남은 승인 2명을 채울 수 있는 사람이 1명뿐입니다. 조직 관리자에게 승인자 추가를 요청하세요.', 0명이면 '지금 승인할 수 있는 사람이 없습니다. …')를 둔다. 승인할 수 없는 요청(`blockedReason`)에는 이름 줄을 두지 않는다.
- 메뉴 배지는 내가 바로 처리할 수 있는 일을 **종류마다 따로** 보인다: 결재 및 요청 '승인 n'(승인할 요청)·'제출 전 n'(제출 전 내 요청: 작성 중과 검토 중, 탭·홈 할 일과 같은 말), 보낼 곳 주소록 '확인 n'(확인할 주소). 0건인 종류는 보이지 않는다. 보이는 배지는 `aria-hidden`이고, 링크 이름에는 '처리할 일 3건: 승인할 요청 2건, 제출 전 내 요청 1건' 한 문장이 들어간다. 중립 색(연한 바탕 + Ink 글자)이며 빨강은 반려·처리 실패에만 쓴다. 메뉴 폭이 모자라면 배지 묶음이 다음 줄 오른쪽으로 내려간다. 받는 주소가 사용 중지되어 승인할 수 없는 요청은 배지에 세지 않고 홈의 위험 항목으로 따로 보인다(A-17).
- 결재 및 요청의 보기 탭에는 같은 서버 건수를 붙인다: '내가 승인할 요청 n', '내가 작성한 요청 · 제출 전 n'(0건이거나 아직 못 받았으면 숫자 없음). 탭 순서와 기본 보기(조직 전체)는 그대로다.
- (A3) '요청 보기'는 한 목록을 거르는 보기라 ARIA 탭(tablist·tab)이 아니라 상태 칩과 같은 **눌림 버튼 묶음**이다: `role="group" aria-label="요청 보기"` 안의 `<button aria-pressed>`(버튼마다 Tab 순서에 있고 Enter·Space로 누른다). 모양(밑줄 탭)·이름·순서·URL(`view`)은 그대로다. 폭이 모자라면 가로 스크롤 대신 줄을 바꾼다(320px에서 모든 보기(역할에 따라 최대 네 개)가 보임, WCAG 1.4.10).

## 주소 대조 띠 (고유 요소)
주소를 4자 묶음으로 나눈다(`AddressStrip`). 묶음 안에서는 줄을 바꾸지 않는다.
- 상세·확인 화면(기본): 전체 묶음을 **같은 굵기·같은 대비**로 보여 준다. 앞·뒤 묶음만 강조하면 앞·뒤만 읽는 습관이 생기고, 앞·뒤만 맞춘 가짜 주소(주소 오염)를 놓치기 쉽다.
- 목록(`compact`): 첫·끝 묶음만(…로 연결). 목록은 찾기용이고 대조는 상세에서 한다.
- 확인 단계(`verify`): 주소 등록의 대조 단계와 주소 확인 카드에서, 원본을 보고 다시 입력할 가운데 8자리(`middleSegment`, 서버가 검사하는 구간과 같음)를 Ink 테두리로 표시하고 "테두리 친 글자는 … 가운데 8자리(MOCK-EVM- 뒤 n~m번째 글자)입니다" 안내를 붙인다. 색만으로 구분하지 않는다. 테두리는 위치를 알려 줄 뿐이며, 글자는 원본에서 보고 입력하게 한다.
- 메모/태그는 주황 배지로 주소 옆에 붙인다. 이 표시는 육안 대조를 돕는 장치일 뿐 안전성 보증 문구를 붙이지 않는다.

## 메뉴·머리글 (A1)
- 메뉴 묶음과 이름은 방향과 쓰임을 말한다(경로·권한은 그대로): [제목 없음] 홈 / **업무** 결재 및 요청, 보낼 곳 주소록 / **자산** 잔고, 자산 활동 내역 / **참고**(조회만 하는 화면) 우리 회사 입금 주소(`/wallets`), 스테이킹 현황(`/staking`), 지원 자산·네트워크(`/tokens`) / **관리** 조직 관리, 감사 기록 / **정보** 마켓 인사이트, 인사이트 자료 관리. 권한이 없는 항목과 빈 묶음은 보이지 않는다. 화면 제목(h1)과 문서 제목은 메뉴 이름과 같다. '주소록'과 '결재'라는 낱말은 유지한다.
- 머리글에는 출금 요청 권한(`request.create`)이 있는 사람에게만, 작성 화면(`/requests/new`)을 뺀 모든 화면에서 주 버튼 '출금 요청 작성'을 조직명과 사용자 영역 사이에 둔다. 이동만 하며(미리 채우는 값 없음) 작성 중인 화면에서는 이탈 확인을 거친다. 560px 이하에서는 '출금 요청'만 보이고 '작성'은 화면 낭독기에만 남긴다(이름은 '출금 요청 작성'). 380px 아래에서는 아이콘만 보이고 이름·툴팁이 '출금 요청 작성'이다. 누르는 영역은 40px 이상이다. 메뉴(슬라이드)에는 넣지 않는다. 홈·결재 및 요청 머리의 같은 버튼은 없앴다(빈 목록의 '첫 요청 작성'은 유지).
- 420px 이하에서는 상단 막대 간격(6px)·로고 높이(16px, 비율 유지)·조직명 앞 여백(4px)·버튼 좌우 여백(6px)을 줄이고 출금 요청 버튼의 + 아이콘을 빼('출금 요청' 글자만) 조직명이 잘리지 않게 한다. 380·390·393px에서 '모의법인 A'·'모의법인 B'가 줄임표 없이 보인다(e2e/a1-wording.spec.ts). 380px 아래에서는 아이콘만 다시 보이고, 상단 막대 간격(4px)·좌우 여백(8px)·로고 높이(14px, 비율 유지)·조직명 앞 여백(2px)을 한 번 더 줄인다(A3 검토, 누르는 영역 크기는 그대로).
- (A3) 조직명 칸이 모자라면(글자 간격을 늘린 경우, 380px 아래) 줄임표 대신 **두 줄까지 줄을 바꾼다**(행간 1.25, 머리글 56px 안). 두 줄로도 모자랄 때만 둘째 줄 끝을 줄인다(…, 전체 이름은 `title`). 보통 간격의 390px에서는 지금처럼 한 줄이다. WCAG 1.4.12 검사 값(줄 간격 1.5·자간 0.12em·단어 간격 0.16em·문단 아래 2em)에서 390px과 320px(출금 요청 버튼이 아이콘만 보이는 경우 포함) 조직명이 잘리지 않는다(e2e/a3-a11y.spec.ts).
- (A3) **메뉴 서랍(860px 이하)**: 「메뉴 열기」로 열면 서랍은 머리글 바로 아래에서 화면 아래 끝까지 이어지고(머리글의 토글 「메뉴 닫기」는 가리지 않고 늘 보임·누를 수 있음), 포커스는 서랍의 첫 메뉴('홈')로 간다. 열려 있는 동안 건너뛰기 링크·환경 띠(로컬)·머리글의 다른 요소·본문·맨 아래 한 줄(공개 데모, A5)은 `inert`라 Tab·Shift+Tab은 토글과 메뉴 사이에서만 돌고(끝에서 처음으로), 화면 낭독기도 서랍 뒤를 읽지 않는다. Escape·막(어두운 바탕) 클릭·토글로 닫으면 포커스는 토글로 돌아온다. 메뉴 링크를 고르면 닫으면서 포커스를 먼저 토글로 돌려준 뒤 이동한다: 화면이 바뀌면 새 화면 제목(h1)이 포커스를 받고, 지금 화면과 같은 경로이거나 작성 중인 화면의 이탈 확인에서 「계속 작성」을 고르면 토글에 남는다(A3 검토: 닫힌 서랍 안의 링크에 포커스가 남아 문서 맨 앞으로 떨어지지 않게). 확인 대화상자는 돌아갈 곳이 포커스를 받지 못하면 화면 제목으로 보낸다. 넓은 화면이 되면 닫힌다. 대화상자 역할(`role="dialog"`)은 쓰지 않고 `nav` 랜드마크('주 메뉴')를 그대로 둔다.

## 홈 '지금 처리할 일' (A1)
- 순서·이동 경로·색·건수는 서버(`/api/dashboard` tasks) 그대로이고, 제목·설명만 화면 문구(`Home.tsx` `TASK_COPY`)로 누가·무엇을·어떻게 하는지 쓴다. 모르는 종류는 서버 문구를 쓴다.
- 사용 대기 주소 경고('사용 대기 중인 새 주소 — 모르는 등록이면 정지하세요')는 정지 권한이 있는 모든 사람의 '지금 처리할 일' 안에 경고 색으로 남긴다(A-31, DEC-003). 조용한 영역으로 옮기지 않는다. 제목이 첫 정지 사유(모르는 등록)를, 설명이 둘째 정지 사유('받는 곳에서 확인되지 않은 주소도 정지하세요')와 정지 방법(「사용 대기 중 정지」)을 맡아 같은 지시를 두 번 쓰지 않는다.
- 승인할 요청·확인할 새 주소·사용 대기 주소에는 할 일 아래 한 줄 목록(최대 3건, 나머지는 '외 n건')을 둔다: '강도윤님 · 0.5 BTC → 그룹사 BTC 보관 이전용 · 4시간 전 승인 요청', '한지수님 등록 · 이름 (자산/네트워크) · 1일 전', '이름 · 등록자 등록 · 확인자 확인 · MM-DD HH:mm부터 사용 가능'(본인이 등록했으면 '내가 등록한 주소 — 내가 요청한 등록이 맞는지 확인하세요', 본인이 확인했으면 '내가 확인한 주소'). 각 줄은 상세 화면 링크이고 선택·일괄 처리는 없다(A-34). 이미 있는 조회 API를 건수가 있을 때만 부르며, 실패하면 할 일 링크만 보인다. 링크 이름에 메뉴 이름('홈'·'결재 및 요청')을 넣지 않는다.

## 결정 카드 (A1)
- 승인자 결정 카드 순서: 제목 → **요약 한 줄**('{요청자}님의 출금 요청: {받는 곳}({상대})에 {수량} (약 평가액) · 목적: … · 승인 x/y명', 받는 곳 이름이 이미 괄호로 끝나면 '{받는 곳} · {상대}에') → **주소록 기록 두 줄**(A2-2, A-32: '등록 한지수 2026-05-28 · 받은 경로 이메일 → 등록자가 다시 확인한 경로 미리 등록된 연락처로 전화' / '확인 서예린 2026-05-28 · 지금 상태 사용 가능 · 사람이 남긴 기록이며 증명이 아닙니다 · 주소 기록 보기'. 다시 확인한 경로는 등록자가 남긴 값이라 '등록자가'를 붙인다(다음 줄의 확인자가 그 경로로 확인했다고 읽히지 않게). 사용 대기를 거친 주소면 상태 바로 뒤에 '(YYYY-MM-DD HH:mm부터)'(괄호는 이 시각 하나뿐). 기록 방식 도입 전 주소는 '받은 경로·등록자가 다시 확인한 경로: 기록 없음(이 기록을 남기기 전에 등록된 주소입니다)', 등록 때 비슷한 주소 경고가 있었으면 경고 색 한 줄 '등록 때 비슷한 주소 경고가 있었습니다 — 등록 사유는 주소 기록 보기에서 확인하세요'이고 이때 '주소 기록 보기' 링크는 둘째 줄 끝이 아니라 이 줄 안으로 옮긴다(링크는 늘 하나, 링크 이름은 줄을 바꾸지 않음). 지금 상태는 15초마다 새로 읽는 요청 응답의 값. 확인자의 연락 경로는 저장하지 않으므로 쓰지 않고, 등록자가 남긴 '확인한 상대·연락처'는 독립 경로로 착각하지 않게 카드에 옮기지 않는다. 주소 조회가 실패하면 '주소 기록 보기' 링크만) → 승인 대상 지문(그대로 카드 안, A-29)과 바로 아래 승인자 쪽 할 일 '요청자에게서 이 지문을 메신저가 아닌 다른 연락 수단으로 받았다면 같은지 대조하세요. 다르면 승인하지 말고 반려하세요.'(선택 단계, 승인 조건은 그대로) → 출금 전 점검 → **지급 근거**(A2b, 아래 '지급 근거' 절: 승인 요청 때 고정된 파일·메모, 없으면 '근거 기록 없음') → 승인 효과 문장 → 되돌릴 수 없음 문장(문구 그대로) → 승인 전 확인(수량 체크 아래 지급 근거가 있으면 '위 「지급 근거」의 문서·메모와 수량을 대조하세요. 요청자가 올린 자료이므로 의심되면 요청자에게 원본을 확인하세요.', 없으면 '이 요청에는 지급 근거가 없습니다(근거 기록 없음). 요청자에게 받은 문서와 직접 대조하세요.'(A2b 전에는 '이 화면에는 근거 문서가 첨부되지 않습니다…'), 주소 체크 바로 위에 전체 주소 대조 띠 '대조할 받는 주소 (네트워크)', 기본 모드라 모든 묶음 같은 굵기. 체크 줄은 누르는 영역 44px 이상, 560px 이하에서 체크 상자 22px) → 결정 버튼 → 마지막 승인일 때만 승인 뒤 흐름 한 줄('처리 결과(처리 완료 또는 처리 실패)는 이 화면의 상태로 표시되고, 완료되면 자산 활동 내역에 출금으로 기록됩니다.').
- 이번 승인으로 필요한 승인 수가 채워지면(표시용 계산, 정족수는 서버가 정함) 효과 문장은 '**이번 승인이 마지막 승인입니다.** 승인하면 바로 수탁사 처리가 시작되고, 그 뒤에는 요청자도 취소할 수 없습니다.'이고 버튼 이름은 **'승인하고 처리 시작'**이다. 아니면 '지금 기준으로 이번 승인은 필요한 승인 y명 중 첫 번째(두 번째 …)입니다. m명이 더 승인해야 처리가 시작됩니다.'와 '승인'이다. '지금 기준으로'를 붙이는 까닭: 이미 승인한 사람에게 승인자 역할을 다시 주면 요청 버전이 그대로인 채 유효 승인 수가 늘 수 있어(다음 새로 고침, 최대 15초 전까지) 화면의 몇 번째가 낡을 수 있다. 바로 아래 '채워지면 바로 처리가 시작'되는 되돌릴 수 없음 문장이 이 경우도 덮는다. 승인·반려 직후 결과 안내도 같은 낱말 '수탁사 처리'를 쓴다. 버튼의 `aria-describedby`는 효과 문장(+ 세 항목 확인 전 안내). 세 가지 확인과 활성 규칙은 그대로다.

## 지급 근거 (A2b, DEC-005)
- 낱말은 늘 '지급 근거'다. 주소의 '메모/태그'(승인 대상 지문에 묶인 값)와 섞이지 않게 '메모'만 따로 쓰지 않고 '지급 근거 메모'로 쓴다(뒤에 흐린 '(설계 가정)'). 문구는 `shared/terms.ts` `PAYMENT_EVIDENCE_TEXT` 하나에서 가져온다.
- 자리: 요청자는 작성 중·검토 중에 요청 내용 카드 바로 아래 편집 카드(일반 `section.card`, 「내용 수정」 중에는 같은 자리에 읽기 카드), 그 밖의 사람과 승인 요청 뒤에는 읽기 카드, 승인자는 결정 카드 안(출금 전 점검 결과 다음, 승인 효과 문장 앞). 결정 카드 안의 블록은 옅은 바탕·얇은 테두리 상자이고 `.rc-*`·`.card-action`·`.btn-primary` 클래스를 쓰지 않는다(`pe-` 접두, A1 순서 검사가 그 클래스로 위치를 잰다).
- 근거가 있으면 맨 위에 출처 안내('요청자가 승인 요청 전에 올린 자료입니다. 문서가 진짜인지, 받는 주소가 맞는지는 이 화면이 확인하지 않습니다. …')를 둔다. 지급 근거는 받는 주소 확인 근거가 아니며, 주소 대조 띠·끝자리 재입력(A-05·A-07)은 그대로다.
- 근거가 없으면 굵은 '근거 기록 없음'과 설명 한 줄을 점선 테두리의 중립 바탕에 둔다. 성공 색(녹색)도 경고 색도 쓰지 않는다(근거가 있다는 것이 문서가 진짜라는 뜻이 아니고, 없다는 것이 잘못이라는 뜻도 아니다). 설명 한 줄은 보는 사람에 맞춘다: 결정 카드(승인자)는 '요청자가 지급 근거 파일이나 메모를 남기지 않았습니다. 수량과 받는 곳은 요청자에게 받은 문서와 직접 대조하세요.', 읽기 카드(요청자·감사 담당자·이미 결정한 승인자 등)는 사실만 '이 요청에는 지급 근거 파일이나 메모가 없습니다.'이고 승인 대기 중인 자기 요청을 요청자가 볼 때만 뒤에 "승인자 화면에도 '근거 기록 없음'으로 보입니다."를 붙인다. 요청자나 감사 담당자에게 대조하라고 하지 않는다.
- 파일 목록(`<ul aria-label="지급 근거 파일">`): 줄마다 72px 미리 보기(PNG·JPEG만, `alt="{이름} 미리 보기"`, 투명 부분은 옅은 격자, 못 불러오면 '미리 보기를 불러오지 못했습니다(공개 데모는 서버마다 데이터가 따로입니다).') 또는 PDF 아이콘 칸 → 이름(굵게, `overflow-wrap:anywhere`로 카드 안에서 줄바꿈) → '형식 · 크기 · SHA-256 앞 12자리 xxxxxxxxxxxx'(해시는 고정폭) → '첨부 {이름} · YYYY-MM-DD HH:mm' → 버튼('내려받기', 요청자 편집 카드만 '삭제'). 버튼의 접근 가능한 이름에는 파일 이름이 붙는다(sr-only). 560px 이하에서는 버튼이 아래 줄로 내려가고 누르는 높이가 44px 이상이다. PDF는 화면에서 열지 않고 내려받기만 한다.
- 편집 카드 순서: 제목 → 경고 Notice '모의 환경입니다. 실제 인보이스나 개인정보가 담긴 파일은 올리지 마세요.' → 안내 → 지급 근거 메모(입력 `#pe-note`, 300자, 'n/300', 「메모 저장」) → '지급 근거 파일' 제목과 한도('PDF·PNG·JPEG · 파일당 2MB · 요청당 5개까지') → 목록 또는 빈 안내 → 「파일 추가」(숨은 파일 입력을 여는 보이는 버튼, 5개이거나 올리기를 꺼 두었으면 비활성과 이유 한 줄) → 진행·결과 한 줄(`role="status"`, '올리는 중… (1/3)'·'파일 2개를 붙였습니다') → 올리지 못한 파일 목록(위험 Notice `role="alert"`, 같은 파일은 정보 Notice). 줄마다 '{파일 이름}: {이유} {다음에 할 일}'이다. 화면이 보내기 전에 거른 파일(형식·빈 파일·크기·개수·읽기 실패)도 서버 응답과 같은 문장 짝(`PAYMENT_EVIDENCE_TEXT.upload`)을 써서, 예를 들어 SVG·HEIC는 '이 파일 형식은 올릴 수 없습니다. PDF·PNG·JPEG 파일만 받습니다. 문서는 PDF로, 화면이나 사진은 PNG·JPEG로 저장해 올리세요. 아이폰 사진(HEIC)은 JPEG로 내보내 올리세요.'다. 삭제는 `ConfirmDialog`(destructive, '돌아가기' 초기 포커스)로 묻고, 지운 뒤 「파일 추가」로 포커스를 옮긴다.
- 승인 요청 카드의 버튼 위 한 줄: '지급 근거(파일 n개·메모)가 승인자에게 함께 보입니다. 승인 요청을 보내면 바꿀 수 없습니다.' 또는 "지급 근거 없이 보내면 승인자 화면에 '근거 기록 없음'으로 보입니다." 저장하지 않은 메모가 있으면 그 아래 경고 색 한 줄. 새 요청 작성 양식의 요청 목적 아래에는 흐린 한 줄로 초안 저장 뒤 붙인다는 것만 알린다.

## 결정 근거·감사 기록 내보내기 표지 (A2)
- 결정 근거 한 줄(A2-3): 요청 상세 '처리 기록'의 승인·반려 줄과 감사 기록 화면 '내용' 칸 아래에 흐린 13px 글자로 '결정 당시 역할: 승인자(역할 변경 기록 기준) · 필요 승인 수에 셈 · 결정 때 본 승인 대상 지문 17B9 C2A0 9F3E 11D4(지금 요청과 같음)'를 쓴다(감사 CSV 열과 같은 `decisionEvidenceText`). 화면의 다른 낱말과 맞춘다: '정족수' 대신 '필요 승인 수'('승인 x/y'·'필요한 승인 수'와 같은 말), 지문은 결정 카드 제목과 같은 '승인 대상 지문'. 지문 네 묶음만 고정폭·한 줄(`.mono.nowrap`)로 두어 390px 카드에서도 묶음 중간에서 줄이 바뀌지 않는다. 역할 조각은 감사 기록 조회 권한자(감사 담당자·조직 관리자) 화면에만 있고, 역할 변경 기록이 없으면 '결정 당시 역할: 알 수 없음(역할 변경 기록 없음)'(기록상 역할이 비어 있던 '없음(역할 변경 기록 기준)'과 구분). 지금 요청의 지문과 다르면 그 조각만 위험 색 굵게('(지금 요청과 다름)'), 표 지문이 없으면 '승인 대상 지문 기록 없음(이 기능 도입 전 결정)', 승인했지만 세지 않은 표는 '필요 승인 수에 세지 않음', 역할 기록상 승인 권한이 없으면 아래에 경고 색 줄 '역할 변경 기록상 이때 승인 권한이 없습니다 — 기록을 확인하세요'. '승인 권한 확인됨' 같은 보장 말은 쓰지 않는다.
- 감사 기록 화면의 내보내기 버튼 아래(내보내기 권한자에게만) 흐린 한 줄: '내보낸 파일 맨 위에 기간·조건·내보낸 사람·시각·해시 연결 확인 결과를 담은 표지가 붙습니다.' 이 줄은 'CSV 내보내기' 링크의 설명(`aria-describedby="audit-export-hint"`)으로 이어져 화면 낭독기가 링크에서 함께 읽는다. 표지의 '보관용 값'은 이번 내보내기 기록이 남기 전 값이라 그 뒤에 '(이 내보내기 기록이 남기 전 값입니다. 내보낸 직후 감사 기록 화면은 …건수가 1건 많고 마지막 기록 해시도 다릅니다)'를 붙인다. 표지 형식은 `docs/api.md` '감사 기록 CSV'.

## 출금 전 점검 목록 (A1)
- 보이는 순서는 주의 → 확인 불가 → 기준 이내다. 주의·확인 불가는 펼쳐 두고(세부·기준·「사유 필요」·진행 사유 입력 또는 저장된 사유), '확인 불가'에는 '자료가 부족해 판단하지 못한 항목입니다. 문제가 없다는 뜻은 아닙니다.'를 붙이고, 요청자 화면(작성 미리 보기·내 요청·검토 카드)에서 사유가 필요 없는 항목이면 '…아니며, 진행 사유는 적지 않아도 됩니다.'로 끝낸다(승인자·감사 담당자의 할 일로 읽히지 않게).
- 기준 이내 항목은 네이티브 `<details>` 묶음('기준 이내 n건 · 기준과 세부 내용 보기')에 접어 둔다. 항목은 빼지 않으며(같은 마크업·기준), 묶음은 중립 색(녹색 아님)이다. 사유가 필요하거나 저장된 사유가 있는 항목은 결과와 관계없이 접지 않는다. 주의·확인 불가가 없으면 '주의·확인 불가 항목이 없습니다.'를 쓴다. 요약 줄과 기준 각주(설계 가정, 보증 아님)는 접히지 않으며, 기준 이내 묶음이 있는 모든 점검 목록(검토 카드, 결정 카드, 제출 뒤 결과, 작성·검토 중 요청의 읽기 전용 목록)에 같은 각주를 둔다. 기준 이내 묶음은 중요 고지가 아니다.

## 자주 묻는 질문·접는 영역 (A1)
- 보낼 곳 주소록과 결재 및 요청에 '자주 묻는 질문'을 네이티브 `<details>`(처음에는 한 줄로 접힘, Enter·Space로 펼침)로 기존 안내 아래에 둔다. 기존 규칙을 다시 설명할 뿐이며, 정책 숫자는 정책 값에서 가져와 '설계 가정'을 붙인다. 답에는 링크를 두지 않는다. 중요 고지는 여기로 옮기지 않는다.

## 쉬운 말 (A1)
- '고유부'는 서버 오류 문구(`CONFIRM_MIDDLE_MISMATCH`)와 맞추려 가운데 8자리 입력 도움말 괄호 안에만 한 번 쓴다('MOCK-EVM- 뒤의 글자(고유부)를 1부터 셉니다'). 레이블·단계·띠 안내는 'MOCK-EVM- 뒤 17~24번째 글자'로 쓴다.
- '예약'은 홈에서 '출금 요청에 묶임', 잔고 머리글·좁은 화면 설명에서 '묶인 수량(예약)'으로 쓴다. 예약은 승인 대기와 처리 중 모두 유지되고 처리가 끝날 때 풀리므로(서버 `settleProcessing`), 두 경우에 맞는 말을 쓴다(설명 문장 `GLOSSARY.reserved`도 '승인 대기·처리 중인 출금 요청에 묶여 있는 수량'). 총 평가액(홈·잔고) 바로 아래에는 '스테이킹 현황의 맡긴 수량·보상은 이 합계에 넣지 않았습니다(모의 데이터).'를 짧게 둔다(잔고 화면 아래 긴 문장은 그대로).
- 커스터디는 '수탁사(KODA)', 이 환경에서는 '모의 커스터디'로 쓴다. 네트워크 칸 도움말에는 거래처에 물을 질문 한 줄을 붙인다.
- 상태 이름, '승인 대상 지문', '주소록', '결재'는 바꾸지 않는다(서버 메시지·테스트와 같은 단어).

## 표
- 머리글 13px 굵게, 숫자 열 오른쪽 정렬, 행 구분선 1px, 자산 그룹 시작 행은 2px.
- 긴 텍스트는 `cell-wrap`(최대 360px 줄바꿈). 홈은 1100px 이하 한 열에서 「지금 처리할 일 → 보유 자산 → 진행 중인 요청 → 최근 활동」 순서.
- 560px 이하에서는 표를 행마다 레이블이 붙은 카드로 쌓는다(`table-stack` + 셀의 `data-label`): 홈 보유 자산, 자산 활동 내역(종류·수량 → 상대방 → 일시·상태 → 네트워크·참조), 감사 기록(행동·번호 → 일시·수행자 → 내용), 조직 구성원, 주소록(**상태 배지는 이름 옆 첫 줄**). 잔고는 자산마다 한 덩어리(평가액·모의 시세 + 지갑별 보유·사용 가능·묶인 수량(예약))로 보이고, 넓은 표 머리글의 용어 설명이 없으므로 덩어리 위에 '사용 가능'·'묶인 수량(예약)'의 뜻을 같은 문장으로 펼쳐 둔다. 표 영역 안의 가로 스크롤로 열을 숨기지 않으며, 보이는 셀은 56px보다 좁아지지 않는다(e2e/responsive.spec.ts).
- 감사 기록의 번호는 조직 안의 기록 순서(1부터)다. 무결성 오류 위치도 같은 번호로 알린다.
- 주소록은 한 번에 최대 500개를 보여 준다. 넘으면 잘렸다는 안내와 함께 검색·필터를 권한다.
- 목록 탐색은 탭마다 다르게: 활동 내역·감사 기록은 페이지(크기 선택), 요청은 페이지 10건 기본, 주소록은 페이지 없이 검색·필터, 인사이트는 "더 보기". 필터·페이지는 URL에 저장해 새로고침·상세 복귀 후 유지하고, 필터를 바꾸면 1페이지로 돌아간다.

## 폼
- 단계별 `fieldset`(번호 원 + 질문형 legend). 앞 단계가 끝나야 다음 단계가 활성화된다.
- 레이블은 항상 보이게, 도움말은 레이블 아래, 오류는 입력 아래 빨간 글자. 입력에는 `aria-invalid`와 `aria-describedby`(도움말+오류)를 공통 `Field`가 붙인다. 서버 오류는 필드 오류와 하단 안내(원인 + 복구 행동, `role="alert"`) 두 곳에 표시하고 첫 오류 입력으로 포커스를 옮긴다.
- 모든 제품 폼은 `noValidate`(브라우저 말풍선 대신 서버·앱 검증). 실패해도 입력은 지우지 않는다(보안상 다시 받아야 하는 값 제외).
- 여러 줄 입력은 공통 `TextareaAuto`: `resize: none`, 최소 rows 높이에서 내용에 맞춰 늘고 상한을 넘으면 내부 스크롤.
- 작성 중 이탈: 인앱 이동은 앱 확인 대화상자(「계속 작성」 초기 포커스 / 「작성 내용 버리기」), 창 닫기는 표준 beforeunload. 저장 성공 직후에는 경고하지 않는다. 입력을 브라우저 저장소에 보관하지 않는다.
- 세션 만료 중 작성 화면이면 화면을 떠나지 않고 같은 계정 재로그인 대화상자를 띄운다(입력은 메모리에만 유지).

## 대화상자
- 공통 `ConfirmDialog`(네이티브 `<dialog>` 모달). 브라우저 `confirm()` 금지. 제목은 행동, 본문은 대상·영향·되돌릴 수 있는지. 되돌릴 수 없는 행동은 빨간 확정 버튼(동사: 「사용 중지」「요청 취소」), 안전한 선택(취소/돌아가기)에 초기 포커스. 처리 중에는 대화상자를 닫지 않고 중복 확정을 막으며, 실패하면 대화상자 안에 원인과 복구 행동을 보인다. 닫히면 트리거로, 트리거가 사라졌으면 화면 제목으로 포커스를 돌린다. 좁은 화면에서는 버튼을 세로로 쌓는다.

## 검색
- 공통 `SearchField`: 입력은 즉시 보이고 조회는 300ms 뒤, 한국어 조합 중에는 조회하지 않음, Enter·지우기(×, Escape)는 즉시. 지우기 후 입력으로 포커스. 검색어·필터·페이지는 URL에 저장.

## 기타 전역 규칙
- 문서 제목: `화면 제목 · KODA 법인 대시보드 (개발 환경)` (`PageHeader`가 설정).
- 스크롤바: `:root`의 표준 `scrollbar-width: thin`·`scrollbar-color`, `scrollbar-gutter: stable`(대화상자 스크롤 잠금 시 폭 변화 방지).
- 복사 버튼은 성공(「복사됨」)과 실패(원인과 직접 선택 안내)를 모두 보이고 읽어 준다.
- 되돌릴 수 없는 행동 전에는 원본을 보고 끝자리를 다시 입력(붙여넣기 차단)하고 확인 체크를 받는다. 주소 등록과 주소 확인에서는 가운데 8자리도 원본을 보고 다시 입력한다.
- 상세·작성 화면(`.page-narrow`)은 목록 화면과 같은 1240px 상자(가운데 정렬)를 쓰고 그 안의 내용만 최대 820px로 줄인다. 그래서 화면 폭과 관계없이 목록 화면과 왼쪽 기준선이 같다(e2e/display.spec.ts, 1920px).

## 고지·환경 표시
- 로컬 실행의 상단 고정 띠: "개발 환경 · 개발용 로그인 · 모의 데이터 · 모의 커스터디" 뒤에 실제 자산 전송·운영 인증이 일어나지 않는다는 문장. 560px 이하에서는 네 항목만 남기고 뒤 문장을 줄인다. 운영 연동 전에는 제거하지 않는다. 로컬 로그인 화면은 '개발용 로그인입니다' 안내 상자를 그대로 둔다.
- (A5) 공개 데모(`DEMO_PUBLIC=1`)에는 상단 띠와 로그인 화면 안내 상자가 없다. 모든 화면(로그인 포함) 맨 아래에 작은 한 줄 "모의 데이터 · KODA 공식 서비스 아님"만 둔다(`DemoFooter`, 저장소 소유자 요청, DEC-004). 규칙: 문서 흐름의 마지막 요소(`<footer>`, contentinfo 랜드마크)로 두고 `fixed`·`sticky`로 고정하지 않는다(내용·포커스를 가리지 않으므로 `scroll-padding-bottom`이 필요 없다, WCAG 2.4.11). 짧은 화면에서는 셸(`grid-area: foot`)·로그인 화면의 최소 높이로 화면 아래 끝에 붙는다. 글자 12px, `--ink-2` 글자에 `--paper` 바탕(7.4:1), 가운데 정렬, 좁은 화면·확대에서는 낱말 단위로 줄을 바꾼다. 알림 영역(`aria-live`·`role="status"`)에 넣지 않고 문구를 바꾸지 않는다. 메뉴 서랍이 열려 있는 동안에는 서랍 밖이라 `inert`다. 팝업·대화상자로 알리지 않는다. 데모 인스턴스가 바뀌면 본문 위에 처음 화면으로 돌아가는 안내를 띄우는 것은 그대로다(docs/deploy-vercel.md).
- 상단 막대의 조직명은 길면 이름만 두 줄까지 줄을 바꾸고(그보다 길면 둘째 줄 끝만 …, A3) '모의' 표시와 '출금 요청 작성' 버튼은 줄이지 않는다. 560px 이하에서 로그아웃은 아이콘 버튼(이름 「로그아웃」은 화면 낭독기에 그대로)이다.
- 중요 고지(주소록 '사용 가능'의 의미, 네트워크 선택 위험, 인사이트 이용 고지)는 본문 크기 글자로, 접거나 회색으로 약화하지 않는다. 자주 묻는 질문과 점검의 '기준 이내' 묶음만 접는다(A1).

## 접근성 기본값
건너뛰기 링크, 화면 전환 시 h1로 포커스 이동(첫 화면 제외), 보이는 포커스 링(3px 파랑), 아이콘 버튼 `aria-label`, 상태 변경 `aria-live`, `prefers-reduced-motion` 존중. axe 자동 검사(WCAG 2.1 A/AA 규칙)를 E2E에 포함한다.

(A3, 공개 데모 접근성 점검 반영 — e2e/a3-a11y.spec.ts)
- **어두운 바탕 위 포커스**: Ink 바탕(다음 할 일 패널) 안 요소는 같은 굵기의 `--focus-on-dark`(#B9F3DD) 링을 쓴다. 어두운 바탕 영역을 새로 만들면 그 안의 `:focus-visible`에도 같은 규칙을 붙인다(링과 바로 옆 바탕 3:1 이상).
- **sticky 머리글과 포커스**: `html { scroll-padding-top: 72px }`(머리글 56px + 여유 16px). 포커스·앵커로 옮긴 요소가 머리글 밑에 들어가지 않는다(1440·390·320px에서 Shift+Tab으로 확인). 머리글 높이를 바꾸면 이 값도 바꾼다. 이 전역 값이 예전 요소별 여백(`.next-action`·`.rc-focus-target`의 `scroll-margin-top: 72px`)을 대신한다. 요소에 `scroll-margin-top`을 다시 두지 않는다(`scrollIntoView`에서 두 값이 더해져 머리글 아래 144px에 놓인다, A3 검토).
- **입력 칸 테두리**는 `--line-input`(3:1 이상). 구분선 색을 입력 칸에 쓰지 않는다.
- **흐린 글자**(`--ink-3`)는 연한 상태 바탕(`*-soft`) 위에서 4.5:1이 안 되므로 쓰지 않는다. 안내 상자(`.notice`) 안의 `.muted`는 `--ink-2`로 보인다.
- **알림 영역**은 처음부터 빈 채로 그려 두고 내용만 바꾼다(첫 메시지와 함께 새로 생긴 영역은 낭독기가 놓치기 쉽다). 비어 있는 동안은 `.live-slot:empty`로 자리를 차지하지 않는다. 주소 형식 점검(`Findings`), 수량 미리 보기(`<output>`), 출금 전 점검 미리 보기 요약(`.rc-live`, 목록 전체가 아니라 '출금 전 점검: 주의 1건, 기준 이내 3건' 한 줄), 결재 및 요청 결과 줄(`.req-result`, '조건에 맞는 요청 0건'까지; 이 화면의 페이지 줄은 같은 내용을 두 번 읽지 않게 알림 영역이 아니다). 새 결과·새 미리 보기를 불러오는 동안은 알림 영역의 앞 문장을 그대로 둔다: 비웠다가 같은 문장을 다시 쓰거나, 앞 결과의 건수를 새 조건과 섞어 먼저 쓰지 않는다(A3 검토, 한 번만 알림).
- **메뉴 서랍**은 위 '메뉴·머리글' 절의 서랍 규칙(포커스 이동·inert·Escape·토글로 복귀)을 따른다.
